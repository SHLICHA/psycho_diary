# 📋 Спецификация обработчиков: `bot/handlers/diary.py` (обновленная версия)

Данный документ описывает обновленные обработчики в модуле `bot/handlers/diary.py`.  
Включает улучшения: вынос бизнес-логики в сервисы, улучшенную обработку ошибок, rate limiting.

> ✅ Обновлено: 2025-10-30  
> 🔄 Изменения: Вынос бизнес-логики, улучшения в API, обработка ошибок, rate limiting

---

## 🧩 `new_entry_simple`

> Упрощенное создание записи с умными подсказками.

- **Функционал**:
  - Использует `SmartPromptManager` для генерации контекстных подсказок.
  - Устанавливает состояние ожидания текста записи.
  - Автоматический fallback на стандартный запрос при ошибках.

- **Вход**:
  - `callback_data`: `new_entry`
  - Триггер: нажатие кнопки "Новая запись".

- **Выход**:
  - Переход в состояние: `DiaryStates.waiting_for_text_entry`
  - Сообщение: умная подсказка или стандартный запрос
  - Клавиатура: `get_cancel_keyboard`
  - При ошибке: fallback на стандартный запрос

## 📝 `process_any_entry` (обновленный)

> Обработка записей с улучшенной обработкой ошибок и rate limiting.  
> **Важно:** Основная бизнес-логика (создание, анализ, валидация, schedule clarification) вынесена в `diary_service.process_new_entry_use_case`.

- **Функционал**:
  - Валидация входящих сообщений и проверка rate limits.
  - Обработка голосовых сообщений через `process_voice_message`.
  - Вызов `diary_service.process_new_entry_use_case` для основной обработки (включая `schedule_clarification_for_entry` при необходимости).
  - Форматирование итогового сообщения и клавиатуры через presenter/`diary_display_service`.
  - Обработка случая `is_valid=False` (уведомление пользователя).
  - При `needs_clarification`: только FSM + отправка вопросов (доменный schedule уже в сервисе).
  - Интеграция с `SmartPromptManager` для генерации подсказки после сохранения.

- **Вход**:
  - Состояние: `DiaryStates.waiting_for_text_entry`
  - Тип события: `message.text` или `message.voice`
  - Декоратор: `@async_error_handler('diary_handler')`

- **Выход**:
  - При успехе: `entry_saved` с анализом, оценкой, рекомендацией, возможным заданием, кнопками.
  - При `is_valid=False`: уведомление о невалидности, кнопки повтора.
  - При `needs_clarification`: отправка вопросов, переход в состояние `asking_clarifying_questions`.
  - При rate limit: `rate_limit`
  - При ошибке: `error_processing`
  - Уведомление `SmartPromptManager` о сохраненной записи (асинхронно).
  - Очищает состояние FSM (если не требуются уточнения).

## ❓ `process_clarification_answers` (обновленный)

> Обработка ответов на уточняющие вопросы с улучшенной логикой.  
> **Важно:** Основная бизнес-логика (маппинг ответов, анализ, обновление состояния) вынесена в `diary_service`; render — в `build_entry_saved_view`.

- **Функционал**:
  - Обработка текстовых и голосовых ответов.
  - Формирование словаря ответов через `diary_service.build_clarification_answers_map`.
  - Вызов `diary_service.process_clarification_answers_use_case` для основной обработки.
  - Render через `build_entry_saved_view` (без повторной доменной записи анализа).
  - Очистка состояния FSM после обработки.

- **Вход**:
  - Состояние: `DiaryStates.asking_clarifying_questions`
  - Тип события: `message.text` или `message.voice`
  - Данные FSM: `clarifying_entry_id`, `clarification_questions`

- **Выход**:
  - При успехе: обновленный анализ с кнопками.
  - При ошибке: `error_processing`
  - Очищает состояние FSM.

## 📖 `view_entry_history` (обновленный)

- **Функционал**:

  - При наличии записей: первая запись с навигацией (◀️▶️), кнопками (редактировать, удалить, анализ дня, удалить все, назад).

  - При ошибке: `error_generic` (всплывающее).

## 📄 `_show_entry_page` (вспомогательная)

> Отображение одной страницы записи (пагинация) с форматированием и клавиатурой.  
> **Важно:** Содержит логику форматирования текста и клавиатуры для Telegram. Подготовка данных *может быть* вынесена в `diary_service`.

- **Функционал**:
  - Форматирование заголовка с локализованной датой и индексом.
  - Отображение текста записи, анализа (`PsychoAnalysis`), комментария пользователя.
  - Отображение оценки настроения.
  - Проверка, был ли день проанализирован (`CombinedDiaryEntry.is_analyzed`) для формирования клавиатуры.
  - Интеграция с системой пагинации и клавиатурой `get_entry_page_keyboard`.
  - Обработка ошибок временных зон при получении даты.
  - Использование `edit_or_send_message` для надежного обновления сообщения.

- **Вход**:
  - `message`: сообщение для редактирования/отправки
  - `user`: объект пользователя
  - `entry`: текущая запись
  - `entries`: список всех записей дня (для пагинации)
  - `target_date`: целевая дата (для проверки `is_analyzed`)
  - `language`: язык интерфейса

- **Выход**:
  - При успехе: отредактированное/отправленное сообщение с отформатированной записью и клавиатурой.
  - При ошибке: `error_generic` (в сообщении).
