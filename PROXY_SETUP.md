# Настройка прокси для Телеграм бота

## Обзор

Этот бот поддерживает работу через HTTP и SOCKS прокси для обхода блокировок. Настройки прокси задаются в файле `.env` и применяются ко всем компонентам бота:
- Основной процесс бота (polling)
- Celery задачи (напоминания, мотивации, анализ и т.д.)

## Быстрый старт

### 1. Получите прокси

Вам нужен прокси-сервер, который может подключаться к серверам Telegram. Рекомендуются SOCKS5 прокси, так как они лучше подходят для Telegram.

Источники прокси:
- Платные VPN/прокси сервисы (надежнее)
- Собственный прокси-сервер (VPS в другой стране)
- Бесплатные прокси (менее надежно, для тестирования)

### 2. Настройте .env файл

Скопируйте `.env.example` в `.env` (если еще не существует):

```bash
cp .env.example .env
```

Откройте `.env` и настройте прокси:

#### Вариант A: SOCKS5 прокси с аутентификацией (рекомендуется)

```env
TELEGRAM_PROXY_URL=socks5://username:password@123.45.67.89:1080
```

#### Вариант B: SOCKS5 без пароля

```env
TELEGRAM_PROXY_URL=socks5://123.45.67.89:1080
```

#### Вариант C: HTTP прокси

```env
TELEGRAM_PROXY_URL=http://username:password@123.45.67.89:8080
```

#### Вариант D: Без прокси (закомментировать)

Если блокировки сняли или прокси не нужен:

```env
# TELEGRAM_PROXY_URL=
```

## Формат URL прокси

```
протокол://[логин:пароль@]хост:порт
```

### Поддерживаемые протоколы:
- `socks5://` — **рекомендуется** (лучше всего для Telegram)
- `socks4://` — альтернатива
- `http://` — работает, но менее надежен

### Примеры:

```env
# SOCKS5 с логином/паролем
TELEGRAM_PROXY_URL=socks5://myuser:mypass@proxy.example.com:1080

# SOCKS5 без пароля
TELEGRAM_PROXY_URL=socks5://192.168.1.100:1080

# HTTP прокси
TELEGRAM_PROXY_URL=http://proxy.mycompany.com:8080

# HTTP с аутентификацией
TELEGRAM_PROXY_URL=http://user:pass@proxy.mycompany.com:3128
```

## Проверка работы

### 1. Перезапустите бота

После изменения `.env` перезапустите все сервисы:

```bash
# Если используете Docker:
docker-compose down
docker-compose up -d

# Если запускаете вручную:
# Остановите текущие процессы и запустите заново
python manage.py runbot
```

### 2. Проверьте логи

В логах вы должны увидеть сообщение о подключении через прокси:

```
INFO - Создание сессии с прокси: socks5://user:pass@host:port
INFO - Bot экземпляр создан успешно
```

### 3. Протестируйте бота

Отправьте сообщение боту в Telegram. Если он отвечает — прокси работает!

## Troubleshooting

### Бот все равно не работает

1. **Проверьте формат URL:**
   - Убедитесь, что протокол указан правильно (`socks5://`, `http://`)
   - Проверьте, что хост и порт верные
   - Если есть логин/пароль, убедитесь, что они указаны до `@`

2. **Протестируйте прокси отдельно:**

   ```bash
   # Для SOCKS прокси (нужен curl с поддержкой SOCKS):
   curl --proxy socks5://user:pass@host:port https://api.telegram.org
   
   # Для HTTP прокси:
   curl --proxy http://user:pass@host:port https://api.telegram.org
   ```

3. **Проверьте доступность прокси:**

   ```bash
   # Проверка соединения с прокси:
   ping 123.45.67.89
   
   # Проверка порта:
   nc -zv 123.45.67.89 1080
   ```

4. **Попробуйте другой прокси:**
   - Бесплатные прокси часто не работают
   - Используйте проверенные платные сервисы

### Ошибки в логах

**Ошибка: `Connection refused` или `Connection timeout`**
- Прокси-сервер недоступен
- Неверный хост или порт
- Брандмауэр блокирует соединение

**Ошибка: `Authentication failed`**
- Неверный логин или пароль
- Прокси не поддерживает этот метод аутентификации

**Ошибка: `Proxy error`**
- Прокси-сервер не поддерживает нужный протокол
- Попробуйте `socks5://` вместо `http://`

### Временное отключение прокси

Если прокси стал не нужен, закомментируйте строку:

```env
# TELEGRAM_PROXY_URL=socks5://...
```

И перезапустите бота.

## Рекомендации по выбору прокси

### ✅ Хорошо:
- **Платные SOCKS5 прокси** от проверенных поставщиков
- **Собственный сервер** (VPS) в другой стране с установленным Squid/3proxy
- **VPN с функцией SOCKS прокси** (например, Mullvad, NordVPN)

### ⚠️ Средне:
- Бесплатные прокси из проверенных источников (для тестирования)
- Публичные прокси-листы (нестабильно)

### ❌ Плохо:
- Случайные открытые прокси без аутентификации
- Медленные прокси с высоким пингом (>500ms)

## Настройка собственного прокси-сервера

Если у вас есть VPS в стране, где Telegram не заблокирован:

### Установка 3proxy (простой SOCKS прокси):

```bash
# На сервере Ubuntu:
sudo apt update
sudo apt install 3proxy

# Создайте конфиг /etc/3proxy/3proxy.cfg:
cat > /etc/3proxy/3proxy.cfg << EOF
nserver 8.8.8.8
nscache 65536
timeouts 1 5 30 60 180 1800 15 60
users username:CL:password
socks -p1080
EOF

# Запустите:
sudo systemctl enable 3proxy
sudo systemctl start 3proxy
```

Затем используйте в `.env`:
```env
TELEGRAM_PROXY_URL=socks5://username:password@YOUR_VPS_IP:1080
```

## Безопасность

⚠️ **ВАЖНО:**
- Никогда не коммитьте `.env` файл в Git!
- Используйте надежные пароли для прокси
- Регулярно меняйте пароли прокси
- Проверяйте, что прокси использует шифрование (SOCKS5 предпочтительнее)

## Как это работает технически

Бот использует библиотеку `aiohttp` для HTTP-запросов к Telegram API. При указании `TELEGRAM_PROXY_URL`:

1. Создается `AiohttpSession` с параметром `proxy=TELEGRAM_PROXY_URL`
2. Все запросы к `api.telegram.org` идут через указанный прокси
3. Это работает для:
   - Получения обновлений (polling)
   - Отправки сообщений
   - Любых других API вызовов

Настройка применяется централизованно через:
- `bot/bot_instance.py` — основной экземпляр бота
- `bot/utils/bot_factory.py` — фабрика для Celery задач

3. Протестируйте прокси отдельно от бота
4. Попробуйте альтернативный прокси-сервер
