# Telegram-бот психологического дневника

## Описание

Этот Telegram-бот предоставляет интерактивную платформу для ведения психологического дневника с использованием искусственного интеллекта (ИИ). Он помогает пользователям отслеживать свои мысли, эмоции, события и получать персонализированные инсайты, рекомендации и поддержку в развитии самосознания.

## Основные функции

### 1. Ведение дневника:
- **Создание записей:** Пользователи могут создавать текстовые или голосовые записи о своих мыслях, чувствах и событиях дня.
- **Валидация ИИ:** Новый ввод может быть проверен ИИ на соответствие определённым критериям. Невалидные записи могут быть отклонены.
- **Редактирование и удаление:** Записи можно просматривать, редактировать и удалять через архив.
- **Комментирование:** После получения анализа пользователь может добавить свой комментарий к записи, который может быть вовлечён в последующий анализ ИИ.

### 2. Анализ записей:
- **Мгновенный анализ:** Каждая запись сразу анализируется ИИ, который присваивает оценку настроения (1-10), даёт краткий комментарий и персональные рекомендации.
- **Уточняющие вопросы:** В зависимости от содержания, ИИ может задать уточняющие вопросы для более глубокого понимания.
- **Оценка анализа:** Пользователи могут оценивать качество анализа (1-5 звёздочек), что может использоваться для обратной связи в системе.

### 3. Полный анализ дня:
- **Объединение записей:** Все записи пользователя за один день объединяются в `CombinedDiaryEntry`.
- **Глубокий анализ:** ИИ проводит комплексный анализ всех записей дня, выявляя тренды настроения, ключевые темы, эмоциональные паттерны, инсайты и даёт расширенные рекомендации.
- **Доступ к анализу:** Полный анализ дня доступен в архиве на следующий день. Его можно запустить вручную (за токены или с подпиской).

### 4. Еженедельный анализ:
- **Обзор недели:** Один раз в неделю ИИ формирует общий отчёт за неделю, включающий сводку, сравнение с предыдущей неделей, обновлённый психологический профиль и статистику.
- **Обновление профиля:** Используется для корректировки и обновления психологического портрета пользователя.

### 5. Терапевтические задания:
- **Назначение:** На основе записей ИИ может предлагать персональные задания для развития осознанности, работы с эмоциями и проработки внутренних процессов.
- **Выполнение:** Пользователь описывает, как он выполнил задание, и свои ощущения.
- **Анализ выполнения:** ИИ анализирует выполнение задания, даёт комментарий и рекомендации. За выполнение некоторых заданий начисляются токены.
- **История заданий:** Пользователь может просматривать выполненные, пропущенные и текущие задания.

### 6. Отслеживание прогресса:
- **Уровень осознанности:** Уровень (1-10), который повышается с регулярным использованием бота и может влиять на количество доступных заданий в день.
- **Серии (Streaks):** Отслеживание количества дней подряд, когда пользователь делает запись.
- **Награды за streak:** За достижение 7, 30 и 365 дней подряд пользователь получает токены.
- **Графики настроения:** Визуализация настроения пользователя за последние дни.
- **Восстановление прогресса:** Возможность восстановить пропущенные дни (за токены).

### 7. Профиль пользователя:
- **Личные данные:** Имя, дата рождения, увлечения, факты о жизни.
- **Психологический портрет:** Динамически формируемое описание личности, включающее черты характера, ценности, триггеры, сильные стороны, зоны роста, привычки, навыки, стремления и общий текстовый портрет. Портрет обновляется на основе записей и анализа ИИ.
- **История профиля:** Хранение снимков психологического профиля пользователя в разные моменты времени.
- **История транзакций:** (Планируется) История покупок и трат токенов.
- **Единый email identity:** При сохранении email одновременно обновляется `email_hash`, поэтому конфликт email корректно определяется между Telegram, MAX и web-аккаунтами и может запускать flow подтверждения merge.

### 8. Чат с психологом ИИ:
- **Интерактивный диалог:** Пользователь может вести диалог с ИИ на тему своего самочувствия, мыслей, получать поддержку и ответы на вопросы.
- **Токены/Подписка:** Использование чата может стоить токены (если нет подписки) или быть неограниченным (с подпиской).

### 9. Подписка и токены:
- **Подписка (Премиум):** Позволяет получить доступ к автоматическому анализу дня, неограниченному чату с психологом ИИ и другим расширенным функциям.
- **Токены:** Внутренняя валюта бота. Тратится на автоматический анализ дня (без подписки), чат с психологом ИИ (без подписки), восстановление пропущенных дней.
- **Пополнение:** Токены можно купить или получить за выполнение заданий и поддержание streak.

### 10. Настройки:
- **Язык:** Выбор русского или английского языка.
- **Часовой пояс:** Указание города или выбор из списка для корректного отображения времени.
- **Уведомления:** Включение/отключение напоминаний.
- **Автоанализ:** Включение/отключение автоматического анализа дня (требует токены или подписку).
- **Лимит заданий:** Количество заданий в день (зависит от уровня осознанности).

### 11. Помощь и поддержка:
- **Разделы помощи:** Подробные инструкции по использованию всех функций, часто задаваемые вопросы, руководство, информация о подписке и токенах, приватности и контактах.
- **Обратная связь:** Возможность отправить текстовое, голосовое сообщение или фото с обратной связью или вопросом.

### 12. Онбординг:
- **Приветствие и инструкция:** Новый пользователь проходит краткий онбординг, получает информацию о функциях и соглашается с условиями использования.
- **Анкета:** Пользователь может заполнить краткую анкету, которая помогает ИИ лучше понимать его с самого начала.

### 13. Приватность:
- **Шифрование:** Все личные данные и записи шифруются.
- **Удаление данных:** Пользователь может инициировать удаление своего аккаунта и всех связанных данных в любое время через настройки.

### 14. Архив:
- **Календарь:** Удобный календарь для просмотра записей по датам.
- **Пагинация:** Навигация между записями в пределах одного дня.

### 15. Подсказки:
- **Персонализированные подсказки:** ИИ может генерировать индивидуальные подсказки или темы для размышлений в новых записях.

## Технологии

- **Python**
- **aiogram** (библиотека для Telegram Bot API)
- **Django** (веб-фреймворк)
- **DeepSeek API** (для ИИ-анализа)
- **sentence-transformers** (локальная семантическая кластеризация list-полей в precleanup)
- **PostgreSQL** (или другая СУБД, используемая с Django)
- **Redis** (для кэширования и рейт-лимитов)

## Заметки по multi-platform identity

- Пользователь может существовать только с `telegram_id`, только с `max_id` или сразу с обоими идентификаторами.
- Во внутреннем коде нельзя повторно искать пользователя только по `telegram_id`: для MAX/web-сценариев он может быть `NULL`.
- Если нужно перечитать пользователя из БД после изменений, используйте `pk/id` как platform-agnostic идентификатор.

## Конфигурация локальной кластеризации (precleanup)

Перед полным профильным анализом list-поля (`life_facts`, `core_values`, `triggers` и др.) проходят локальную семантическую кластеризацию. Для запуска используются переменные окружения:

- `SENTENCE_TRANSFORMERS_MODEL_NAME` (по умолчанию `ai-forever/sbert_large_nlu_ru`)
- `SENTENCE_TRANSFORMERS_DEVICE` (`cpu`/`cuda`)
- `SENTENCE_TRANSFORMERS_HOME`
- `HF_HOME`
- `TRANSFORMERS_CACHE`
- `PROFILE_CLUSTER_SIMILARITY_THRESHOLD` (глобальный fallback-порог)

Дополнительно можно задавать пороги по полям:

- `PROFILE_CLUSTER_SIMILARITY_THRESHOLD_LIFE_FACTS`
- `PROFILE_CLUSTER_SIMILARITY_THRESHOLD_HOBBIES`
- `PROFILE_CLUSTER_SIMILARITY_THRESHOLD_CORE_VALUES`
- `PROFILE_CLUSTER_SIMILARITY_THRESHOLD_TRIGGERS`
- `PROFILE_CLUSTER_SIMILARITY_THRESHOLD_STRENGTHS`
- `PROFILE_CLUSTER_SIMILARITY_THRESHOLD_AREAS_FOR_GROWTH`
- `PROFILE_CLUSTER_SIMILARITY_THRESHOLD_PRACTICAL_PATTERNS`
- `PROFILE_CLUSTER_SIMILARITY_THRESHOLD_ASPIRATIONS`

Правила агрегации метаданных в precleanup:

- `weight`: максимум в кластере
- `frequency`: сумма в кластере
- `added_at`: самая ранняя дата (`min`)
- `last_seen`: самая поздняя дата (`max`)
- `is_stale`: `true` только если stale все элементы кластера

## REST API: единый формат ошибок

Для всех API-ошибок используется единый JSON-контракт:

```json
{
	"error": {
		"code": "machine_readable_code",
		"message": "Human readable message",
		"details": {
			"field": ["Validation message"]
		}
	}
}
```

Пояснения:
- `error.code`: стабильный код для логики фронтенда.
- `error.message`: текст для отображения пользователю или логов.
- `error.details`: опциональный объект с деталями валидации/исключения.

Типовые коды:
- `validation_error`
- `authentication_failed`
- `permission_denied`
- `not_found`
- доменные коды endpoints, например `invalid_token`, `invalid_date_format`, `user_comment_required`.

## Локальный запуск (оба бота)

Один скрипт поднимает web + celery + Telegram + MAX (нужны `.env`, `venv`, PostgreSQL, Redis):

```bash
./start.sh              # полный стек (логи в терминал, Ctrl+C — стоп)
./start.sh telegram     # только Telegram (+ web/celery)
./start.sh max          # только MAX
./start.sh docker       # docker compose (оба бота и инфраструктура)
./start.sh stop         # остановить локальные процессы
./start.sh help
```

Логи сервисов идут в тот же терминал с префиксами `[web]` / `[celery]` / `[tg]` / `[max]`.
Остановка стека — **Ctrl+C**.

### Webhook vs polling (auto)

Единый переключатель — `BOT_PUBLIC_DOMAIN`:

| `.env` | MAX | Оплата |
|--------|-----|--------|
| `BOT_PUBLIC_DOMAIN=` (пусто) | `polling` (`runmaxbot`) | webhook выключен; sync через API |
| `BOT_PUBLIC_DOMAIN=https://www.psychodiary.ru` | `webhook`, URL `…/api/max/webhook/` | `…/api/payments/webhook/` |

- Пустой `MAX_TRANSPORT_MODE` = auto по домену; явные `polling`/`webhook` перекрывают auto.
- Явные `MAX_WEBHOOK_URL` / `PAYMENT_WEBHOOK_URL` перекрывают URL, собранные из домена.
- После появления HTTPS: пропишите домен, `./start.sh register-webhook`, в кабинете ЮKassa укажите payment URL из `check_max_bot_config`.

В режиме `polling` у `runbot` принудительно `MAX_TRANSPORT_ENABLED=false`, MAX — отдельно через `runmaxbot`.
В режиме `webhook` отдельный `runmaxbot`/`max_bot` не нужен (events → `web`).

## Запуск MAX-бота (runtime)

Минимальная подготовка `.env`:
- `MAX_TRANSPORT_ENABLED=true`
- `BOT_PUBLIC_DOMAIN=` пусто для polling, или `https://www.psychodiary.ru` для webhook
- `MAX_TRANSPORT_MODE=` пусто (auto) либо явно `polling`/`webhook`
- `MAX_BOT_TOKEN=<token>`
- `MAX_API_BASE_URL=https://platform-api2.max.ru`
- `MAX_API_TIMEOUT_SECONDS=10` (обычные API-вызовы)
- `MAX_POLLING_TIMEOUT_SECONDS=30` (long poll; HTTP-таймаут клиента автоматически больше этого значения)
- CA Минцифры (обязательны для TLS к platform-api2):
  `MAX_API_CA_CERT_PATHS=russian_trusted_sub_ca_2024_pem.crt,russian_trusted_root_ca_pem.crt`
- Опционально явные URL: `MAX_WEBHOOK_URL`, `PAYMENT_WEBHOOK_URL`
- Для admin-команд в MAX без связанного Telegram: `DEVELOPER_MAX_USER_ID=<max_user_id>`
  (также работают `is_staff` / `MONITORING_PRIVILEGED_USER_IDS` / `DEVELOPER_CHAT_ID` при linked telegram_id)

Admin в MAX (при включённом транспорте): `/admin`, `/stats`, `/feedbacks`, `/broadcast`.

После `message_callback` первый ответ бота идёт через `POST /answers` с `message` (+ `notification`). В polling нельзя перезаписывать `MaxStateStore` целиком перед dispatch — это стирало `fsm_state` онбординга и подставляло `error_generic`.
Также: tasks (`tasks` / `/tasks`), profile (`user_profile` / `/profile`), therapy (`start_therapy_chat`).

Проверка конфига перед запуском:

```bash
python manage.py check_max_bot_config
```

Запуск выделенного MAX runtime локально:

```bash
python manage.py runmaxbot
# или: ./start.sh max
```

Запуск в Docker Compose (выделенный сервис):

```bash
docker compose up -d max_bot
# или полный стек: ./start.sh docker
```

Health endpoint webhook:

```bash
GET /api/max/webhook/
```

### Объединение аккаунтов Telegram + MAX

При конфликте email (`EMAIL_MERGE_CONFIRMATION_ENABLED`) оба канала подтверждают merge.
Если включён `EMAIL_MERGE_EXECUTE_ENABLED`, после dual-confirm выполняется data-merge:

- survivor — больше записей дневника (при равенстве — более ранний аккаунт);
- дневник, платежи, токены и ids каналов → survivor;
- премиум: сумма оставшихся дней; токены: сумма балансов;
- профиль: один непустой → перенос пакета; оба непустые → Celery-пересборка;
- дни текущей календарной недели → очередь переанализа;
- donor → `merged_*` без `telegram_id`/`max_id`, hard-delete через 30 дней;
- утренние/напоминания уходят в оба канала (`send_message_to_user`).
