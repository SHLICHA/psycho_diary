# 📌 Введение в задачу

У нас уже существует Telegram-бот с активной базой пользователей.
Каждый пользователь в боте однозначно определяется по `telegram_id`.

Сейчас мы запускаем веб-версию продукта, которая должна:

* работать как самостоятельный продукт (web-first)
* быть полностью синхронизирована с Telegram-ботом
* использовать **одну и ту же модель пользователя (`User`)**

---

# 🎯 Цель

Реализовать систему авторизации и регистрации, которая:

1. Позволяет пользователям заходить:

   * через Telegram
   * через email + пароль

2. Позволяет **связывать Telegram и Web аккаунты**

3. Исключает (или минимизирует) создание дублей пользователей

---

# ⚠️ Важные ограничения

1. `telegram_id` уже используется в продакшене → менять нельзя
2. Уже есть база пользователей → нужно учитывать существующих
3. Нельзя ломать текущую логику бота
4. Нельзя автоматически создавать дубли пользователей

---

# 🧠 Общая логика системы

* Один пользователь = одна запись в `User`
* У пользователя может быть:

  * только Telegram
  * только email
  * оба способа входа

---

# 🔄 Основные сценарии

---

## 1. Telegram → Web

### 📌 Триггер:

Пользователь вводит команду:

/web

---

### 📌 Что делает бот:

1. Генерирует одноразовый токен (TTL 5–10 минут)
2. Сохраняет его (user_id, expires_at, is_used)
3. Отправляет ссылку:

https://app.com/auth/telegram?token=XYZ

---

### 📌 Что делает backend (web):

Endpoint:
GET /auth/telegram?token=XYZ

Логика:

1. Проверить токен (валидность, TTL, не использован)
2. Найти пользователя
3. Авторизовать (создать сессию)
4. Пометить токен как использованный

---

### 📌 Первый вход в web

Если у пользователя не задан email/пароль:

Показать экран:

"Привет, {first_name} 👋
Заверши регистрацию"

Поля:

* email
* пароль

После этого:

* сохранить email
* установить пароль

---

## 2. Web регистрация

### Endpoint:

POST /auth/register

Поля:

* email
* password

---

### Логика:

1. Проверить уникальность email
2. Создать пользователя

---

### После регистрации:

Показать:

"Аккаунт создан. Подключите Telegram для использования бота"

Кнопка:
[Подключить Telegram]

---

## 3. Web → Telegram (привязка)

---

### 📌 На web:

1. Пользователь нажимает "Подключить Telegram"
2. Генерируется link_token (TTL ~10 мин)
3. Пользователь получает ссылку:

https://t.me/your_bot?start=link_ABC123

---

### 📌 В боте:

Команда:
/start link_ABC123

---

### 📌 Логика:

1. Найти token
2. Получить пользователя (web)

---

### Проверка:

Если telegram_id НЕ привязан:
→ привязать к текущему пользователю

Если telegram_id уже существует:
→ НЕ создавать нового пользователя

Показать сообщение:

"Этот Telegram уже привязан к другому аккаунту"

---

# 🔐 Авторизация

---

## Способы входа:

1. Email + пароль
2. Через Telegram (через /web magic link)

---

# 🚫 Важные запреты

1. Нельзя создавать пользователя при каждом /start в боте
2. Нельзя автоматически делать merge пользователей
3. Нельзя создавать пользователя, если:

   * email уже существует
   * telegram_id уже существует

---

# 🧩 Необходимые доработки

---

## 1. Таблица токенов

Создать модель:

* token (string, unique)
* user (FK)
* expires_at
* is_used
* type (login / link)

---

## 2. Endpoint'ы

Реализовать:

* GET /auth/telegram
* POST /auth/register
* POST /auth/login
* POST /auth/link-telegram (генерация link_token)

---

## 3. Бот

Добавить:

* команду /web
* обработку /start link_XXX
