# 📋 Диагностика работы бота

## 🎯 Что добавлено

### 1. Детальное логирование прокси
Теперь при запуске бота вы увидите:
```
============================================================
ИНИЦИАЛИЗАЦИЯ БОТА
============================================================
✓ Bot token найден (длина: 46)
============================================================
СОЗДАНИЕ СЕССИИ БОТА
============================================================
✓ Найден прокси: http://***:***@192.166.153.170:8000
✓ Сессия с прокси создана успешно
============================================================
```

### 2. Логирование входящих сообщений
Добавлен middleware, который логирует ВСЕ сообщения от Telegram:
```
============================================================
ПОЛУЧЕНО ОБНОВЛЕНИЕ ОТ TELEGRAM
Тип события: Message
От пользователя: 123456789 (@username)
Текст: /test_ping
============================================================
```

### 3. Диагностическая команда `/test_ping`
Отправьте боту `/test_ping` и получите:
```
🏓 PONG!
✅ Бот работает!
✅ Polling активен
✅ Бот получает сообщения
✅ Прокси работает (если настроен)
Если вы это видите - всё отлично! 🎉
```

## 🔍 Как проверить работу бота на сервере

### Шаг 1: Перезапустите контейнеры
```bash
cd /path/to/psycho_diary
docker-compose down
docker-compose up -d --build
```

### Шаг 2: Проверьте логи telegram_bot
```bash
docker-compose logs telegram_bot | tail -100
```

**Что должны увидеть:**
```
✓ Bot token найден
✓ Найден прокси: http://***:***@192.166.153.170:8000
✓ Сессия с прокси создана успешно
✓ Bot экземпляр создан успешно
ЗАПУСК POLLING
Если видите это сообщение - бот начал polling
```

### Шаг 3: Проверьте, получает ли бот сообщения
Отправьте боту `/test_ping` и посмотрите логи:
```bash
docker-compose logs -f telegram_bot
```

**Если бот получает сообщения:**
```
ПОЛУЧЕНО ОБНОВЛЕНИЕ ОТ TELEGRAM
Тип события: Message
От пользователя: ВАШ_ID (@username)
Текст: /test_ping
```

**Если НЕ получает:**
- В логах НЕТ "ПОЛУЧЕНО ОБНОВЛЕНИЕ"
- Значит проблема на уровне polling/getUpdates

### Шаг 4: Проверьте celery_worker (там тоже логи)
```bash
docker-compose logs celery_worker | grep -A5 "BOT_FACTORY"
```

## ⚠️ Возможные сценарии

### Сценарий A: Бот НЕ получает сообщения
**Симптомы:**
- Отправляете `/test_ping` - нет ответа
- В логах НЕТ "ПОЛУЧЕНО ОБНОВЛЕНИЕ ОТ TELEGRAM"
- В логах ЕСТЬ "ЗАПУСК POLLING"

**Причина:** Сервер не может подключиться к Telegram API даже через прокси

**Решение:**
1. Проверьте, что прокси рабочий:
```bash
# Внутри контейнера:
docker-compose exec telegram_bot bash
curl --proxy http://JN8R8w:QZPAby@192.166.153.170:8000 https://api.telegram.org
```

2. Если прокси не работает:
- Проверьте, что IP:порт доступны
- Проверьте логин/пароль
- Попробуйте другой прокси

### Сценарий B: Бот получает, но НЕ отвечает
**Симптомы:**
- В логах ЕСТЬ "ПОЛУЧЕНО ОБНОВЛЕНИЕ"
- Но НЕТ ответа пользователю

**Причина:** Ошибка при отправке сообщения

**Решение:**
```bash
docker-compose logs telegram_bot | grep -i error
```

### Сценарий C: Celery задачи падают
**Симптомы:**
```
Request timeout error
Не удалось отправить напоминание
```

**Решение:**
```bash
# Проверьте, что celery_worker использует прокси:
docker-compose logs celery_worker | grep "BOT_FACTORY"
```

Должно быть:
```
BOT_FACTORY: Создание бота для Celery задачи
✓ Найден прокси: http://***:***@192.166.153.170:8000
✓ Сессия с прокси создана
```

## 🐛 Диагностика прокси

### Проверка изнутри контейнера:
```bash
# Зайдите в контейнер:
docker-compose exec telegram_bot bash

# Проверьте, доступен ли прокси:
curl -v http://JN8R8w:QZPAby@192.166.153.170:8000

# Проверьте, работает ли через прокси к Telegram:
curl --proxy http://JN8R8w:QZPAby@192.166.153.170:8000 \
  https://api.telegram.org/bot<TOKEN>/getMe
```

### Проверка формата URL:
```
✅ Правильно:
http://user:pass@host:port
socks5://user:pass@host:port

❌ Неправильно:
http://user:pass@host:port/ (слэш на конце)
http://host:port@user:pass (перепутан порядок)
```

## 📊 Быстрая диагностика

Выполните эту команду на сервере:
```bash
docker-compose logs telegram_bot 2>&1 | grep -E "(ИНИЦИАЛИЗАЦИЯ|Создание сессии|Запуск polling|ПОЛУЧЕНО ОБНОВЛЕНИЕ|ОШИБКА|ERROR)"
```

**Хороший вывод:**
```
ИНИЦИАЛИЗАЦИЯ БОТА
Создание сессии с прокси
✓ Сессия с прокси создана успешно
ЗАПУСК POLLING
ПОЛУЧЕНО ОБНОВЛЕНИЕ ОТ TELEGRAM
```

**Плохой вывод:**
```
ИНИЦИАЛИЗАЦИЯ БОТА
✗ ОШИБКА при создании сессии с прокси: ...
```

## 💡 Полезные команды

```bash
# Логи бота в реальном времени:
docker-compose logs -f telegram_bot

# Логи celery worker:
docker-compose logs -f celery_worker

# Логи с фильтрацией по слову:
docker-compose logs telegram_bot | grep "прокси"

# Перезапуск только бота:
docker-compose restart telegram_bot

# Проверить, запущен ли контейнер:
docker-compose ps

# Зайти в контейнер:
docker-compose exec telegram_bot bash
```
